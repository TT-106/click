## 2. 展开口径(假设,全部记录在 JSON `assumptions`)

- 场景A:每级从**空成品库存**独立展开;场景B:按 工坊→炉窑→水井→仓库→营舍→园圃→补给所→地图室 连建,全局共享批余量。
- 固定普通路线:木板/绳=工坊,布=工坊,砖/炭/铜/铁=炉窑;nails 替代组默认选铁(空库存无从判断"储备充足",按主干金属,可复现)。
- 假设所需工位等级已存在(与设计7.3算例口径一致);使用基础时间,未叠加 L2/L3 速度倍率(升级后的加速会使连建场景实际更快,此处保守)。
- `ceil(缺口/批产量)` 决定批次;批余量入池复用;g 与件数量纲分开,不合并为"总件数"。

## 4. 与 R50 实测的关系(量纲不同,不可混算)

- R50 样本(本轮 100 种子×8 趟)是**旧抽象负重**(归仓 P50=78/趟)与整数件数;上表是**未来公斤/克制**成本。**不能把 77 抽象负重当 77 kg**,也不能虚构"每趟掉 10kg 铁矿"。
- 新石料/黏土/水/食物在真实会话中**根本未生成**(来源未实现)。因此"每个目标几趟可负担"目前**算不出真实答案:待新经济供给实现**。唯一可说的是相对结构(见 §6)。
- 已按 `synthetic-scenario.json`(标记 synthetic-scenario,候选模型)重算设计7.3示例:每趟额外净收益 木14kg/纤维0.6kg/铁矿2kg → 工坊二级需 木28/纤1.2/铁4 ≈ **2 趟**;若从空仓还需攒 12kg 木料日常保护量 → 木料总需求 40kg ≈ **3 趟**。与设计原文一致,但明确标注:这是候选参数演算,**不是 R50 实测,不代表每个种子都会这么掉落**。

## 5. 设计问题(发现即记录,原设计不自动改)

1. **炉窑三级 133 分(炉窑 130 分)是全表最长工序**:24 砖+6 铁锭+4 铜锭全在一号工位串行,没有并行空间;建议 proposal:三级件拆分到二级先备砖,或降砖量。
2. **仓库三级(炉窑73分)与水井三级(炉窑82分)炉窑时间显著高于其工坊时间**——三级升级的瓶颈全部压在炉窑,这表示同一炉窑加工队列会竞争；设计所述资格链可并行不等于所有工序同时完成。
3. **铁锭紧固替代范围未定案**(继承 unlock-summary 问题):工具无法判定哪些等级的铁锭可用铜 1:1 替代。
4. **批余量税**:所有含炭/砖链的展开都会剩 0.5–1.5kg 木炭(整批规则的自然结果);场景B显示余量可跨目标复用,但目标级预留系统(设计6.4)实现时必须把"余炭"计入,否则会重复烧炭。
5. **速度倍率未计入展开**:L2 后工坊×1.1 会让连建场景的后续木板更快;当前保守用基础时间,速度提升可能减少对应工位负载，但跨工位依赖仍会增加工期，不能据此保证实际完工早于上表。

## 6. 结构性观察(相对结论,不依赖新供给)

- 六个"原料直接建造"的一级设施(工坊/炉窑/水井/园圃/补给所/地图室)都不需要任何加工品；R54用配方/建筑联合启动可达性检查，在原料充足假设下无自举矛盾。
