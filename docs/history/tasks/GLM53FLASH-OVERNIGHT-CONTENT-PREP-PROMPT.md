## 5. T1：把60类物品录入为可靠数据

输出：`content-prep/expedition-v1/items.json`、`items.csv`、`schema-notes.md`；校验工具 `tools/content-prep/validate.mjs`。

分六批录入，顺序和数量为：原料20、加工12、消耗10、工具6、装备8、研究收藏4。每批录入后检查唯一ID、名称、计量和设计出处，再继续下一批。**记录全部60个ID，不只做几条示例。**

最小字段约定：

```json
{
  "schemaVersion": 1,
  "status": "planned-not-wired",
  "items": [
    {
      "id": "wood",
      "name": "木料",
      "category": "raw",
      "measure": { "kind": "mass", "unit": "g", "quantumG": 100 },
      "unitMassG": null,
      "phase": "A",
      "sources": ["林地倒木", "可靠近营地拾枝"],
      "uses": ["木板", "木炭", "初级建筑"],
      "icon": { "semanticId": "material.wood", "status": "registered" },
      "designRef": "ECONOMY-BASE-DESIGN-V1.md#5.1",
      "notes": []
    }
  ]
}
```

mass数量本身是克，所以 `unitMassG:null`，不是“每克再乘1000”。count有正整数件数和正整数单件质量克；instance用实例接口，标准质量或设计范围单列。类别与计量类型不能混为一谈。药剂250g含包装，空水袋200g与水分别算，装备栏/背包的同一实例只算一次。

图标字段：当前已注册填registered；只存在候选原图填candidate；缺图填missing。不能填一个不存在的semanticId后说“图标都已就绪”。可临时预览通用图标但应显示“占位图”，数据保留缺口。phase A/B/C按原设计启用条件填写，不能把未来战斗用品标成今天可用。

CSV从JSON生成，使用UTF-8，字段包含ID/中文名/类别/计量/克数/阶段/来源/用途/素材状态；不要维护两份人工改动的主表。

## 6. T2：配方录入与量纲检查

输出：`recipes.json`、从它生成的`recipes.csv`、`recipe-issues.md`；扩展同一个校验器。

逐条覆盖设计第6章的三张配方表、正文写明的材料替代、工具柄替代、两种药剂替代，以及水井/园圃生产。每条有ID、工位/等级、阶段、输入、输出、整批基础时间毫秒、外部来源、替代组和设计出处。

约定：

- 原料/散装产物数量以整数g录入；件数以整数件录入；时间2分钟=`120000 ms`。
- 一批木炭：输入wood=4000g，输出charcoal=2000g，时间180000ms。需求1000g仍做整批，余1000g入仓。
- “铜或铁”“兽骨或甲壳”存成 `anyOf` 的独立选项，不是把两者放普通inputs一起扣。校验每个分支的引用与质量。
- 实例升级标 `operation:upgrade-instance`，明确目标ID、输入旧实例、输出原实例、升级后质量与材质；不伪装成制作第二把新武器。
- 水井/园圃有明确外部来源和条件；不是零输入套利配方。基础产线目标和加工生产目标记录分开。
- 告诉工具哪些配方在stage未启用消费者之前隐藏。无真实战斗也不应显示药剂可用。
- 没有明确数值的提灯持续时间、伤害和环境状态，留null＋问题，保持原设计；不得“凭常识”补出新规则。

## 11. T7：成本展开与有限的平衡结论

输出：`building-cost-analysis.json`、`building-cost-analysis.csv`、可读报告；工具`tools/content-prep/analyze-costs.mjs`。

这是离线计算，不是新经济运行时。只实现一个小算法：按选择的固定配方递归展开建筑投入，`ceil(需求/每批产量)`决定批次，记录剩余产物与工位时间。保留g和count的量纲，不把它们加成总件数。遇到循环输出错误、路径和涉及的ID，不猜答案。

必须先通过两个人工算例：

1. 木板8块：木料24000g，8批、工坊16分钟。
2. 工坊二级：木板8 + 绳2 + 铁锭2000g，展开木料28000g、纤维1200g、铁矿4000g；余木炭1000g；工坊20分钟、炉窑11分钟。两工位并行不意味着20+11=31分钟，再加建造2分钟。仅全部材料齐备时22分钟是该例最短路径参考，不能把所有建筑都用max工位时间当精确调度。

然后展开8栋×3级的全部成本（含免费一级）；给每一项量纲、批数、依赖工位、剩余物和设计问题。

当前R50样本与未来成本量纲不同。你可以另列**明确采用设计迁移表的假设换算**，但仍缺石料/纤维/水/黏土等新供应与消费。计算不了真实可负担趟数时写“待新经济供给实现”，不要把旧抽象负重77当77kg，不把未实现原料虚构为每趟掉10kg。

允许输入一个标`synthetic-scenario`的参数文件，重算设计中的14kg木/0.6kg纤维/2kg铁矿额外净收益示例，标示候选模型；不能和真实结果混表。净收益仅扣日常与非目标消费，本目标燃料在成本展开计算一次。

产出有价值的建议：哪几级依赖太多、哪些替代未明确、什么物品暂只有未来用途、哪些收益只有数值而无新行为。建议写proposal，原设计不自动改。
