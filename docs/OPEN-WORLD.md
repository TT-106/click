### 世界与生成

- `natural-terrain.js` 用种子与全局整数格坐标采样多尺度连续噪声，生成高度场、湿度场和域扭曲河道。低地成为湖面；环境分类产生林地、草原、湿地和高地。植被密度随生境变化，树干是实际障碍。高度场当前用于分类和选址，**所有可走格的 elevation 仍为 0**；河道也还不是水文汇流模拟。
- `natural-world.js` 以 32×32 格生成区块，导航/绘制窗口为队伍周围 3×3 区块。跨区块时窗口移动，全局坐标不变，支持负坐标。完整区块采用最近使用缓存，上限 25；地形采样、建筑候选与道路也有独立上限。旧区块淘汰后，按相同版本/种子重建。
- 建筑候选在全局 18 格选址单元内进行确定性抖动和概率采样；院落须完全干燥且高度变化平缓。森林边缘优先药师屋，近水优先工坊，普通原野按权重选择工坊或仓房。位置、数量和类型由环境决定，不强制每区三栋。选型数据在 `building-presets.js` 的 `NATURAL_BUILDING_RULES`，房屋占地和门在 `BUILDING_PRESETS`，美术 ID 在资源包。单栋结构和外观仍是预设；当前只有三类外观。
- 邻近的有效建筑候选使用有界、地形计价的 A* 连接道路，避开房屋，占树格则清理树木。长湖面不强行架桥；路线只接受最多四格的直短水段。独立渡口候选也在全局坐标采样，只跨窄水道。允许自然孤岛和断开的道路；不能把不可达目标当作已走通。
- 新世界起点搜索原点附近真实可走地表，并检查至少 32 格的局部连通空间，避免出生在单格树缝或屋内。不通过修地形造出固定起始村庄。

### 探索、渲染与保存

`open-world-session.js` 负责发现、目标、逐格跟随和历史；不引用经典随机流或战斗状态。已发现未到访地点优先，其他情况走向已知区域的未知边界。活动窗口边缘也是扩展候选，回到全部探明的旧区域时仍可走向新区域。没有“整世界探索完成”状态；若当前陆地无法到达新区域，明确显示等待，保留水面和障碍规则。

地图仍是正交逻辑格，显示为 54×26 菱形的 dimetric 投影。相机、导航、地表轮廓和小地图都使用全局坐标及窗口原点；修复 `cellAt` 的越界串行读取。地表过渡只包含已发现格。Renderer 剔除画外物件，缓存视口周围一圈地表和小地图；相机在缓存内平移，发现/室内/窗口变化才重建，避免逐帧重画数千条曲线。树冠遮住队伍时淡化；房屋继续按占地约束前后遮挡，进屋使用室内切面。

新存储键 `C2_OPEN_WORLD_V1`，生成器版本 1。保存种子、版本、全局位置、发现/到访位图、已生成区块、地点进度、剩余路线与步内进度。每个32×32历史区块使用128字节位图再编码；不保存图片或全部区块对象。恢复检验编码、坐标、队伍相邻关系、历史包含关系、真实可走路线与地点。旧 `C2_FOREST_VILLAGE_V1` 原样保留，旧 v2/v3 生成器与恢复接口仍在；当前入口展示新世界，旧村记录尚没有单独的 UI 切换。经典 `C2_V1_001` 不迁移。

当前保存仍受浏览器 localStorage 配额限制，恢复限制每份历史 8192 区块和地点 10000 条，坐标有约一百万格的校验范围。称“连续世界”表示按需扩展与稳定坐标，不能解读成已验证的无限容量。动态地形、砍树、开箱状态尚未实现；静态重建规则以后变更必须提升生成器版本或持久化旧区块/增量，不能直接改版本 1 导致旧记录漂移。

### 验证与后续顺序

新增九项单测覆盖整个区块按不同顺序生成与淘汰重建、负坐标、跨界连续采样、自然建筑选址与类型数量差异、道路/桥实际通行、位图往返、两个种子持续跨区探索、半步刷新续跑和恶意记录拒绝；旧 v3 的两个完整世界指纹也保持。浏览器脚本 `npm run test:village` 已改为实际连续探索、暂停与刷新续接、旧村/经典完整存档隔离、自然生境画面、房屋遮挡/切面、地表缓存像素一致、DPR 2、375px 和退出恢复经典暂停状态。最终退出码写入 `output/open-world/verification/`，截图与诊断在 `output/playwright/open-world/`；生境与建筑姿态截图是同一产品 Renderer 的探明窗口夹具，真实入口截图仍从迷雾开始。

1. **近期**：完善世界生成质量统计与正式美术主题；给建筑、遗迹、营地增加可保存的交互状态和探索收益，形成探索动机。规则数据继续与显示资源分开。
2. **中期**：做单层真实高差、崖壁和坡道通行，区域级聚落与道路网络，增加建筑类型和遭遇；把生成放到后台工作线程。先持久化区块增量和可导出的世界记录，再允许动态场景。
3. **后期**：分块数据库、世界编辑与 Tiled/LDtk 导入、主题/皮肤、自动素材工作流。桥上桥下需要 surfaceId 和分层导航；不能仅加绘制 z 值。当前规则建筑采样仍有选址单元规律，后续可换稀疏点采样/区域规划，不影响资源或 Renderer。
