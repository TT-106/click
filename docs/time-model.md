# 时间模型

经典与原野使用独立时钟；桌面调度是原野的宿主策略，不是修改经典回合规则。

## 经典的六种时间

| 名称 | 语义 |
|---|---|
| 墙钟 | nowMilliseconds/Date.now，用于保存时间戳和离线间隔 |
| tick | requestAnimationFrame 调用 GameLoop.tick，一次调度 |
| 理论帧时长 | 1000/60ms，是模拟换算基准，不保证实际刷新率 |
| 帧差 | 当前与上次 tick 的墙钟差；FPS 统计另读 lastFrameAt |
| 模拟单位 | advanceSimulation 入参为帧当量，可为小数 |
| 回合 | 累计15模拟单位，正常250ms；冷却/再生/持续时间等按 turnNumber |

实现位于 `modules/simulation/loop.js`、`tick.js`、`characters.js` 和 `core/math.js`。伤害/技能/药水等具体阈值只在 [combat](formulas/combat.md) 和 [progression](formulas/progression.md) 维护，避免复制已改名属性。

## 经典离线与暂停

恢复后允许离线、已建队且未胜利、离上次活动超过120秒时开始结算，上限12小时加 offlineTimeBonus。每帧最多200回合，每回合推进15单位并增加250ms已处理时间；完成/取消由 finishOfflineProgress 结束。序列化写当前墙钟，不写上次活动时刻。

allowBackgroundProgress 与大于1秒的 tick 间隔可走同一离线分支并累加待处理时间。离线中不自动保存；harness 必须调 advanceOffline 而非普通 advance。浏览器后台限频属于宿主行为，不能保证真实每秒回调。

持续运行的手动暂停仍更新 lastTickAt，恢复不会补齐所有暂停时间；如果调度本身暂停/被限频，下一次可出现大帧差。暂停不停止绘图，正常自动保存仍可运行；暂停/离线不按普通帧差累计游玩时长。

模拟异常会设置 simulationFault，此后停止模拟、自动保存和游玩时长累计，仍续排帧和按现有条件绘图；重置/合法导入可解除。渲染异常保留日志并继续调度。该可靠性修正不改变正常250ms节拍。

## 原野与桌面

| 状态 | 普通网页原野 | Windows桌面原野 |
|---|---|---|
| 可见且激活 | rAF 驱动，单步墙钟差最多100ms | 独立定时推进，可见约30次/秒绘制 |
| 隐藏/最小化 | 不推进，恢复清帧差 | 约每秒推进小步，不绘图 |
| 用户暂停 | 会话不前进 | 会话不前进 |
| 退出/电脑休眠 | 不补开放世界进度 | 不补开放世界进度；停顿至多补1秒 |

controller 的桌面模拟每次最多补1秒，再拆成不大于100ms的小步保证跟随/导航顺序；速度选择是独立探索倍率。经典在原野观赏时暂停，退出恢复先前暂停状态。短批/加速采样不能等价于一周自然日、真实功耗或休眠恢复验证。

约一周远征是体验目标，采用自然日、有效模拟时长还是离线结算仍未决定。备份留档、材料归仓和生产设计中的毫秒不是这个产品决定的替代品。
