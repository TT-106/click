# Clickpocalypse II 原生桌面重建约定（待共同确认）

本文把已确认的产品目标转成可执行边界。它仍是设计约定，尚待最终共同确认。术语见根目录 `CONTEXT.md`，不可逆取舍见 docs/adr/ 下的 ADR 0001–0012。

## 目标与范围

- 交付不使用 WebView 的 Windows 桌面游戏：包含素材、离线双击运行、可调整窗口并支持全屏。
- 新引擎采用 Godot 4 .NET/C# 展示层和不依赖 Godot 类型的纯 C# 规则核心。现有 JavaScript 引擎只供行为查证；新产品及发行包不导入或包含旧引擎模块。
- 原版玩法、数值、随机调用顺序、回合节拍和像素美术作为本体基准。新引擎不读取旧版存档；首版使用带版本的新存档。
- 本轮建立项目内版本化内容包机制，用不发布的地牢主题、可玩职业、自动施放技能样例验证全链路。正式新增内容以后由玩家按存档显式启用。
- 搜打撤、物资与基地升级、二次元主线和角色获取属于第二阶段。首版先保全原挂机玩法；第二阶段先做可玩的搜打撤竖向样例，再设计主线与角色获取。
- 界面沿用现有深色像素风的辨识度，重新设计桌面布局、文字层级、操作反馈和可读性。第三方浏览器用户脚本及 DOM 接口不属于桌面兼容范围。

## 当前证据与验证断点

- 2026-09-29 只读审计：现有产品的原版脚本依赖为 0；恢复引擎仍有 23 个模块直接依赖 `runtime/game.js`，最大循环依赖组为 41 个模块。这些是当前工作树事实，工作树已有其他未提交修改。
- `REFACTOR_REPORT.md` 的 51 行功能清单可作新引擎功能盘点；其中的历史 PASS 状态不能转移。旧版存档兼容行因本次决策不适用，旧浏览器专属断言须翻译成桌面行为。
- 现有 `test-parity.mjs`、`test-scenarios.mjs`、soak 与性能脚本先载入同一旧存档。新引擎不读旧档，须建立**从未载档的空白开局**对照：相同种子、时钟、组队命令与推进量，比较语义状态、事件轨迹及随机流消费位置。旧档样本仅能在原版测试端辅助研究长尾行为。
- 当前 `build.mjs` 生成静态站点并复制整个 `src`；不能作为原生桌面发行包验收。新包需审计全部文件，确保无 WebView 和旧引擎模块。
- 原版世界地区与城堡在启动时成批建立，地牢楼层多在进入或换层时生成；房间怪物清空不保证掉落、行动队列和寻路都完成结算。原版战斗与掉落共享随机流，直接把新内容插入旧候选表会改变后续结果。内容包生效点需检查完整事务状态，并隔离新内容的随机流与已生成实例的内容版本。
- 当前 10 张运行用 PNG 中，三张主图集通过 JavaScript 坐标表注册约 2,836 个精灵；动画表、CSS 和 HTML 又单独记录了图片路径与裁切坐标。现有构建脚本只检查少数图片是否存在，无法证明所有素材引用、矩形和动画帧有效。

## 系统边界

```text
Godot 桌面层：窗口、输入、像素画面、面板、声音
       ↓ 命令                         ↑ 只读投影与语义事件
应用会话层：命令排序、时间策略、保存、内容包激活事务
       ↓ 显式推进指令                 ↑ 状态变化、事件、随机流位置
纯 C# 规则核心：世界、队伍、战斗、掉落、进度、内容规则

外围适配器 → 应用会话层：存储、操作系统时钟、内容目录
素材目录 → Godot 桌面层：稳定视觉 ID 到纹理区域/动画的映射
```

- 核心独占权威游戏状态、规则内容版本与显式随机流，不引用 Godot、磁盘、墙上时钟、图片或窗口。一次推进只接收有序命令、明确的时间量与不可变内容定义，产生语义事件和只读投影；窗口尺寸、绘图频率及面板操作不能暗中推进规则。
- 应用会话层把正常帧、最小化、休眠、离线和暂停统一转成核心推进指令，并编排内容包安全点、全量校验、备份、激活与原子保存。任一步骤失败后，重启只能看到完整旧态或完整新态，不能留下半启用状态。
- 存储、系统时钟、资源加载均在边界外实现；内容规则使用稳定 ID，核心和存档不保存纹理对象、图集像素坐标或 Godot 路径。Godot 将输入翻译为命令，只根据只读投影和事件绘图。
- Godot 展示层内部再分世界绘制、特效、面板、输入映射与主题布局；场景脚本只处理展示状态和命令派发，不持有战斗、掉落或进度规则。新增面板不应要求修改模拟循环。
- 领域类型、状态字段和命令使用表达游戏含义的现代命名，不移植反编译缩写或全局单例接口。允许复用的纯算法须先单独验证，再以新接口接入。第二阶段只预留长期进度和独立玩法会话的连接边界，不预建万能玩法插件。
- 至少分开编译纯规则核心、应用会话、外围适配器、Godot 桌面和素材导入工具。依赖图无环；不启动 Godot 也能编译和测试规则核心。

## 素材导入与内容引用

- 将现有图片保持为可追溯的原始素材。旧 JavaScript 坐标与动画定义只用于一次性转换和对照；新项目以中性、版本化素材清单作为唯一运行来源，不在构建或运行时加载旧 JS。
- 每个素材条目有命名空间内稳定的视觉 ID、原始文件、像素哈希、裁切矩形或动画帧、方向与用途。界面、世界、物品、角色和技能统一按视觉 ID 解析；不在场景、面板或样式中散落图集坐标。
- 导入器检查包版本及依赖、重复 ID、文件存在与哈希、裁切边界、帧尺寸和方向、内容规则引用。失败时指出包、ID 和文件；不能在正式构建中静默改用空白图。旧图集并非全都可按规则网格切割，转换时逐条核对坐标并做像素对照。
- 新增地图、职业或自动施放技能时，规则定义与视觉素材通过稳定 ID 关联；原始图片、清单、导入结果和最终 Windows 包里的资源都要能追溯到相同版本。像素素材使用最近邻过滤和整数倍呈现。
- 同类型新素材的常规流程是：把图片放进所属内容包，登记视觉 ID 和用途；单张图片默认使用整图，图集或动画显式写裁切与帧；运行导入校验并查看生成的预览；通过后随包构建，无须修改世界绘制或面板代码。新增规则机制则在纯核心中实现和验证，不能靠素材清单偷偷改变本体规则。
- 按已确认的项目内内容包范围，首版由开发者在构建前导入素材，随离线 Windows 包发布；运行时不提供玩家任意图片导入。若以后要支持个人素材，另设计隔离、校验与存档引用边界，不把任意文件直接并入正式内容目录。

## 画面与桌面行为

- 世界逻辑视野保持 740×450，像素图按整数倍和最近邻方式显示。额外窗口空间容纳独立排版的信息与操作面板。
- 在 1280×720 与 1920×1080 的可调整窗口中检查世界地图、地牢、未暂停战斗、自动施放特效、面板文字、焦点与操作反馈；另在当前 Windows 显示器的全屏模式检查留边、布局与输入。
- 调整窗口大小或切换全屏仅改变显示，不推进回合、不消耗随机数。桌面版保留游戏自身的键盘与鼠标操作。
- 自动存档间隔按源码为 300,000 毫秒（5 分钟）；正常关闭应完成原子保存。离线追赶的跳过操作属于原版功能，桌面界面应提供。
- 最小化且开启后台进度时继续模拟并停止绘图；关闭该选项后，恢复窗口时一次大时间间隙最多触发一次原规则的正常模拟调用。休眠与正常关闭后的时间按离线开关、两分钟门槛及原时长上限结算；手动暂停不跨重启保存。

## 存档与内容包

- 默认使用 Windows 用户数据目录。存在显式便携标记时，下次启动使用程序目录；显示当前存档位置，由用户主动复制或导入，两个位置不自动合并。
- 首版有多个独立存档槽，各槽记录已启用的内容包 ID 与版本。保存、备份、导出、导入、重启恢复、损坏档保护和缺失内容提示都须在桌面包内验证。
- 本体内容始终保持原版规则。测试样例包不进入正式内容列表；关闭样例包的存档不得因样例的加载顺序改变随机流或玩法结果。
- 玩家可为已有存档选择新内容包，先记录为待启用。队伍离开当前地牢或城堡、回到世界地图且战斗、掉落、行动均完成结算时，以原子方式先备份再启用；若备份失败则保持待启用状态。已生成的世界、当前实例和已消耗的随机序列不追溯改写。新增地牢主题只用于以后生成的地牢，职业和技能分别在原有选择及学习入口出现。未启用内容不得改变本体随机流；启用后新规则对未来进程的改变须可归因于包版本和随机流。
- 每个槽位同时记录实际启用和待启用的包及版本。已启用包缺失或版本不兼容时，保留原档并暂停载入，显示所需包及版本；补齐内容或执行经过验证的迁移后方可继续。仅待启用包缺失时保留待启用记录并提示，暂停该包的激活；本体进度仍可继续。

## 切换门槛

1. **行为**：以 51 行功能清单为起点，补足源码审计发现的遗漏后重新建矩阵。新引擎从空白开局完成确定性状态与事件对照，覆盖地图生成、行动与战斗、装备和掉落、19 类升级、技能效果、成就、农场、城堡、离线和重开；每项给出可复跑证据。原版不适用的旧档与浏览器脚本条目明确注明原因。
2. **结构**：纯 C# 核心可脱离 Godot 编译和测试；模块、接口与状态以明确的领域名称重建，项目依赖图无环，没有反编译式单字母绑定和大循环依赖。相同种子与命令序列下，改变绘图频率、窗口尺寸和全屏状态不得改变状态、事件或随机流消费。发行包不含旧引擎代码或 WebView。新内容样例从注册、校验、加载、显示、自动施放到存档版本完成闭环。
3. **画面与操作**：两档窗口和全屏的未暂停实战截图经人工审看；无漏绘、裁切、模糊像素、不可读文字或无响应操作。错误日志和异常视为失败。
4. **性能**：以当前 Windows 电脑为验收机器，记录实际显卡；1920×1080 未暂停实战连续 10 分钟，目标 60 FPS、95% 帧耗时 ≤16.7 毫秒、95% 操作到可见反馈 ≤100 毫秒。保留帧时间分布与场景输入，长时间模拟另核查内存与进度。
5. **素材与交付**：缺图、重复 ID、越界裁切、无效动画或包版本错误必须在导入或载入前明确报错；世界、面板与特效使用同一清单。对内容包激活的备份、状态切换及原子保存分别注入失败，重启后只能得到完整旧态或完整新态。完整离线 Windows 桌面包可双击启动，所有素材可加载，保存与重启可恢复；通过后才整体替换产品入口。

## 实施顺序

1. 固定原版空白开局 oracle 和行为清单；把旧存档依赖从新引擎验收脚本中剥离。
2. 建纯 C# 规则核心、应用会话与适配器项目，先实现随机流、时间策略、命令、状态与内容目录，形成可复跑的最小竖向行为切片。
3. 按世界、队伍与 AI、战斗、物品与掉落、进度与升级、离线等行为链逐项实现并对照；每条链先有失败探针，再扩到长程模拟。
4. 将原图集坐标与动画定义一次性转为中性素材清单，核对像素、范围与引用；建 Godot 像素画面与桌面面板，保留原素材，完成两档窗口、全屏与实战视觉验收。
5. 完成新存档双位置、多槽位及按存档启用的内容包样例；完成打包、性能、长时间稳定性和最终功能矩阵后切换。

## 共同确认

以上为设计树已确认分支的合并结果。素材导入使用者范围依据此前的项目内内容包决定暂按开发期导入；待用户确认这份整体约定准确表达目标后，才能据此开始新引擎实现与发行包替换。
