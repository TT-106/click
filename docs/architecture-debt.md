# 当前架构债务与决策依据

结构实测集中在 [WORKSTATE](WORKSTATE.md)；本文件只记录解释、未闭合问题和取舍。完整早期迁移卡、实验与否决记录在 [历史台账](history/architecture-debt-before-governance.md)。

## 事实与含义

- 经典 `game` 仍是共享组合根；39 成员 SCC 和 19 个直接导入者表明运行/视图/存档仍有交织。74 个初始化调用及后挂载原型是实际契约，顺序守卫不能证明依赖已经单向。
- 信息、结果、远征、导航和部分其它视图已有显式输入；统计、点数、物品和素材预览也已形成绑定接口。R40/R41 的结果/远征解耦已经落地，不再列为待开始任务。
- SaveData 已被恢复/序列化引用，多层世界/角色/怪物/点数/地牢 typedef 已接线。剩余弱类型见 [类型债](m10-type-debt.md)，不能再把 save-dto 描述为零引用资产。
- 原野与经典分离，但原野背包身份来自姓名；显示快照不提供永久 ID。恢复时更名被当作离队/加入，材料归仓只是避免损失，不满足背包主人稳定要求。
- 当前静态清单与大量资源/源码仍未跟踪；结构对账以 Git 比较为基准，不能把它对未跟踪目录的零差异解释为已经覆盖。

## 下一步的判断标准

优先做能缩小真实修改传播范围、有独立可观测行为的切片。经典嵌套 DTO 可逐层核对 fixture 和读写点；剩余视图/世界共享状态先找到全部写入者，明确生命周期再收接口。原野先稳定数据源、身份与保存，再引入生产事务。

架构审计只扫描静态导入和部分命名/读写形状；动态属性、DOM 回调、原型挂载和运行时对象替换需要人工核对。单字母归零是 R41 的历史成绩，目前新文件又有一个短绑定；它不等于整个命名恢复失效，也不能继续报告当前全库归零。

## 保留的否决理由

| 方案 | 为什么不采用 |
|---|---|
| 提前计算成就 `partyMaxLevel` | 会改变 `party.cachedMaxLevel` 的写入时间；仅 requirementType 16 用惰性 getter |
| 每条成就各建一次检查数据 | 旧 A/B 实验显示额外分配成本；一次检查共用读取对象，性能数字仍是历史样本 |
| 将遗留建队绕过视图校验 | selectedCharacters 与实际队伍可能脱节；产品与遗留按钮共用 startParty 入口 |
| 单为指标拆分 game 或添加转发包装 | 隐藏耦合而没有减少调用者理解负担；不作为完成依据 |
| 按 PNG 大小推断建筑/Boss 碰撞 | 显示占地与真实通行是不同契约；需要单独规则设计 |
| 用原版怪癖约束原野新身份修复 | 原野不属于原版身份规则；按新系统设计、版本和迁移判断 |

“经济定义唯一来源”与“manifest 导入”没有冲突：前者管理物品/配方/建筑规则，后者管理图片/帧，使用语义 ID 关联。正式经济是采用准备 JSON、生成运行时模块或其它明确来源，仍未定案；文档治理不替用户实施这项架构选择。
