# 素材、地图与动画升级记录（2026-10-04）

本轮针对当前 `main` 的 Web Canvas 运行时。Godot 在独立分支和目录，本轮没有修改其资源适配器。工作树已有的继续征程切片及文档变更全部保留，未提交、未回滚。

## 真实问题与设计选择

旧代码并非所有游戏逻辑都引用像素位置：角色、怪物和许多地形已经使用名称查询 atlas。这部分值得保留。问题出在名称查询之后的契约：Sprite 暴露 `sourceX/sourceY` 和整组固定 `spriteSize`，Canvas、DOM、头像、掉落物与特效各自读取这些字段。它们默认图块正方形、组内同尺寸，并分别承担裁切、偏移和帧选择。地图格子也直接持有 Sprite 对象；替换目录之后旧指针不会自动更新。

因此本轮没有拆开旧图集，也没有引入渲染引擎、数据库或多层 Provider。采用一个资源目录、一种归一帧描述、一个轻量播放器和纯坐标几何：

```text
世界/内容的语义资源 ID
    → 资源目录（旧 atlas 适配 + 新素材包）
    → 帧/动作/方向、尺寸、锚点、视觉占地
    → 场景投影与脚点排序
    → Canvas / DOM 预览
```

独立 PNG、SVG、WebP 和有裁切 metadata 的 atlas 共用此路径。未来打包图集可以改变 `source`，不必改变世界语义、动画选择或 Renderer。

## 实际代码边界

| 位置 | 职责 |
|---|---|
| `rendering/asset-catalog.js` | 按组查询语义 ID、别名替换、共享图片加载、原子发布、错误报告及按组视觉范围缓存 |
| `scripts/import-assets.mjs`、`src/data/assets.generated.js` | 开发期扫描明确的 `asset.json`，读取尺寸、校验文件与帧、生成静态清单；运行时不扫描目录 |
| `rendering/frame.js` | 旧图集像素字段的兼容边界，输出矩形来源、显示尺寸、锚点、偏移和原点 |
| `rendering/presentation.js` | 逐帧缓存、矩形绘制、最近邻采样和物理像素吸附，保留经典地面补边 |
| `rendering/preview.js` | Canvas 外的头像、道具和特效预览；旧窗口集中维护，新帧按目标容器完整缩放 |
| `rendering/projection.js` | 正投影、逆投影、可见地块范围和视觉占地的深度点，无游戏依赖 |
| `rendering/entity-visual.js` | WeakMap 保存播放状态，按模拟时间、动作、方向选择帧，不写实体或存档 |
| `rendering/scene.js`、`world/tile-visuals.js` | 绘制时解析语义 ID，动画帧和世界位置组合；tile 的旧属性通过访问器兼容 |

启动等待素材就绪，加载失败给出明确错误；运行时注册失败保持原资源，修复后可以重试。`replace` 保留旧保存名称，避免一次换皮变成存档迁移。地图资源 ID、播放状态和 `sceneObjects` 不加入旧存档。

## 地图的真实几何与兼容

逻辑地图仍是正交网格，模拟平面一个格子为 27 单位。地块的屏幕基向量是 `(27,13)` 和 `(-27,13)`，所以地面菱形约为 `54×26`，更准确地说是项目的 dimetric 投影，而非根据“45°”称呼假定标准等距。54×54 是旧图集单元尺寸，不是地面菱形高度。

令 `dx=worldX-cameraX`、`dy=worldY-cameraY`，新素材和场景物件统一使用：

```text
screenX = 370 + dx - dy
screenY = 225 + (dx + dy) × 13/27 - elevation
```

370/225 是当前 740×450 逻辑视口中心，CSS 缩放及 DPR 由展示层处理。逆投影使用同一几何；候选窗按地形帧相对于参考点的实际边界扩展，因此基点在视口外的大树或高墙仍能进入画面。角色和物品的尺寸不会扩大地块扫描。

原实现的连续角色投影每格 Y 为 13.5，地块为 13；掉落物另外保留商、余数和整数截断。直接“修正”全部旧素材会改变既有像素结果。本轮明确保留经典分支，新素材使用统一 13/27 几何；更换美术时可逐项迁移，未修改模拟坐标。

角色、地形的默认 `origin={27,40}` 对齐旧地块的地面参考点；新站立素材默认底部中点锚定，地面默认图片中心锚定，透明留白可显式覆盖 `anchor`。图片高宽不参与游戏坐标或碰撞。

前后遮挡按地面接触点的 `worldX+worldY` 排序，大占地物件取 `footprint` 的前沿，可用 `depthOffset` 微调。同深度才比较 `ground/scenery/actor/effect/overlay`，这些名字不是全局固定覆盖层。图片高度不决定谁挡住谁。旧渲染队列和旧相机深度保持；另修复空命令依赖 `1e5` 哨兵、在极端负坐标遮掉有效命令的问题。

`sceneObjects` 可以描述 `visualId`、逻辑 `position`、视觉占地、层级和高度，用于树、家具、建筑等显示对象。它不是已经完成的地图编辑器或持久化场景格式。

## 验证及边界

后续林中旧村已使用这套接口接入 19 个实际外部资源（完整木屋、树木、地面变体与室内物件），资源包按场景延迟加载；前后遮挡新增基于建筑占地的排序约束。该村落批次的历史验收见 [村落实施与验收](OPEN-WORLD.md)。下面的数字保留为初次素材升级批次快照。

初次素材升级批次记录：75项单元与174个语法文件；91/91 原版差分场景；0/1/99/900 回合完整存档 parity。Canvas 经典指纹、原色/DPR 展示、地图移动、源码 E2E、构建与 dist E2E 均通过。图片错误、重复 ID/别名、错误路径、越界裁切、重试注册等由专门单测覆盖。

真实 Chrome 素材验收还验证了：

- 注册新素材并替换现有角色与地块，旧名称和旧 tile 指针正确解析新资源。
- 40×80 与 64×112 帧交替播放，脚点固定在同一屏幕位置；四个行走方向正确。
- 220 像素高墙前后角色遮挡；2×2 视觉占地深度；基点在视口外的 960 像素图片仍被地图绘制。
- 两个场景物件播放 idle；真实角色绘制路径和头像面板显示新帧。
- 展示代码禁止调用 RNG 的情况下仍完成绘制，前后存档原文一致。
- 185 帧旧状态特效的 URL/crop 与旧代码相同，新特效和法术图标完整适配 30×30、29×29 容器。

证据：`output/playwright/assets/diagnostics.json`、`actual-world.png`、`occlusion-and-import.png`；兼容日志为 `output/asset-upgrade-*.log`。截图中的纯色块用于脚点/遮挡反例，不是替换后的正式美术。

留下的具体债务：

1. `footprint` 是视觉排序占地，未实现 Boss 的多格碰撞、寻路或战斗距离。复杂长墙、交叉建筑需要拆成可独立排序的视觉部件；单脚点 painter 排序无法解决所有相交遮挡。
2. 经典地块/角色的 13 与 13.5 历史差异仍存在。新素材已统一，整体旧画面迁移需要有意识地放弃原像素指纹并另做视觉验收。
3. 旧技能特效帧参与伤害结算。本轮只统一绘制入口，保留 `VisualEffect` 模拟步进；扩展技能视觉前应先把伤害事件与播放时间解开。
4. hurt/cast/interact 有播放接口，但未绑定全部战斗事件；death 不延长游戏现有尸体生命周期。八方向 metadata 能导入，但当前自动移动选择是四方向。
5. 已挂载的部分旧 DOM 面板不会自动响应运行时换皮；重新启动加载清单正常，即时注册后需重建相关视图。没有为热刷新调用会消耗随机数的全局 reset。
6. `sceneObjects` 尚不持久化，地图编辑器、皮肤/装备叠加、自动 atlas 打包、外部 Tiled/LDtk 和 Godot 适配均未实现。

建议按三个阶段推进：近期用真实的一套主题及两三个完整角色包校准脚点和方向，继续走本次导入协议；中期补齐显示事件、拆开战斗伤害与特效时钟，并为确有需求的大怪物定义多格占地规则；后续再围绕稳定的语义 ID、世界坐标和帧描述添加编辑器导入、场景持久化与自动打包。无需今天先实现这些工具，也不必再次推翻素材契约。
