# 性能基线（harness CPU 测量，2026-09-26）

> 方法：`scripts/measure-perf.mjs`，在差分 harness（`tests/engine-harness.html`）中用 `performance.now()` 测量，Chrome headless。这是**无渲染循环的纯模拟 CPU 基线**，用于重构回归比较；不代表真实浏览器帧率（真实帧率受渲染/DOM 支配，后续可用 Chrome tracing 补充）。
> 原始数据：`output/perf/perf-baseline.json`（每次运行覆盖）。环境：Node 22 / Win32 / Chrome channel。

## 测量结果

| 指标 | 重构引擎 | 原版 c2.js | 比值 |
|---|---|---|---|
| 回合推进（载入 fixture 后，500 回合均值） | 0.083 ms/回合 | 0.078 ms/回合 | 1.06x |
| 存档序列化（完整 DTO，50 次均值） | 0.11 ms/次 | 0.12 ms/次 | ~1.0x |
| 存档导入（解码+恢复+重建世界+写回） | 23.9 ms/次 | 25.3 ms/次 | 0.94x |
| 离线 1h 结算（18,925 回合） | 176 ms CPU | 164 ms CPU | 1.07x |

*注：离线处理的回合数（18,925 > 14,400）大于 1 小时的名义回合数，因为处理期间 `offlineDuration` 会按帧差累加（原版同构行为，见 facts.md 第 11 条），两端一致。*

## 结论

1. **重构引擎与原版性能持平**（比值 1.0–1.1x，测量噪声范围内）。ES 模块化没有带来可测量的模拟开销。
2. 预算分析：游戏回合节拍为 250ms/回合（`loop.turnDuration`），单回合模拟成本 ~0.08ms，占预算 **0.03%**。模拟不是热点；真实场景的帧时间将由渲染（Canvas/DOM）支配。
3. 存档导入 ~24ms、离线 1h ~176ms，均远低于可感知阈值。
