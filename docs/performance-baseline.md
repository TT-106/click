# 性能基线（harness CPU 测量，2026-09-26）

> 方法：`scripts/measure-perf.mjs`，在差分 harness（`tests/engine-harness.html`）中用 `performance.now()` 测量，Chrome headless。这是**无渲染循环的操作耗时样本**，用于重构回归比较；不代表真实浏览器帧率。页面 rAF 间隔另见 `docs/performance-after.md`。
> 原始数据：`output/perf/perf-baseline.json`（每次运行覆盖）。环境：Node 22 / Win32 / Chrome channel。

## 测量结果

| 指标 | 重构引擎 | 原版 c2.js | 比值 |
|---|---|---|---|
| 回合推进（载入 fixture 后，500 回合均值） | 0.0824 ms/回合 | 0.0764 ms/回合 | 1.08x |
| 存档序列化（完整 DTO，50 次均值） | 0.114 ms/次 | 0.080 ms/次 | 1.43x |
| 存档导入（解码+恢复+重建世界+写回） | 22.4 ms/次 | 30.0 ms/次 | 0.75x |
| 离线 1h 结算（18,925 回合） | 199.8 ms | 251.7 ms | 0.79x |

*注：离线处理的回合数（18,925 > 14,400）大于 1 小时的名义回合数，因为处理期间 `offlineDuration` 会按帧差累加（原版同构行为，见 facts.md 第 11 条），两端一致。*

## 结论

1. 本次样本未见数量级退化；历史样本与本次在存档导入/离线结算上的相对快慢翻转，**无法**凭单次倍数证明性能持平或稳定改善。
2. 游戏回合节拍为 250ms/回合（`loop.turnDuration`），本次单回合耗时 0.0824ms，约占预算 **0.03%**。这是模拟操作耗时，不能推断整个页面的帧率。
3. 本次存档导入与离线结算分别为 22.4ms、199.8ms；是否可感知取决于呈现方式和设备，需真机测量。
