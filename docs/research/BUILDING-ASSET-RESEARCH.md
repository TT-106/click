## 结论

推荐采用「少量有明确职责的基地设施 + 自动补充目标库存」：远征带回原料，基地做成建材、工具和补给，再支持下一次远征。生产建筑值得增加，但它们应加工探索所得或提供少量基础保障，不应成为无限产矿、替代外出探索的印钞机。

视觉上继续使用完整单体建筑；规则保存设施身份、等级、配方、库存和生产状态。房屋图片不规定建筑功能，更不能从 PNG 尺寸推导仓库容量或导航占地。现有三栋木屋的来源和新候选同为 rubberduck，便于建立过渡主题；新包偏朴素中世纪预渲染风格，**不是二次元正式美术**。

用户随后明确希望更精致的建筑，并询问 GPT Image。已实际使用内置 image_gen 生成 [透明工坊样板](../../output/imagegen/building-concepts/workshop-v1.png)，作为手绘二次元主题参考；它和下方下载素材分开保存，不继承这些CC0素材的许可。生成提示词、透明通道验证与未适配事项见 [经济设计的美术样板](../ECONOMY-BASE-DESIGN-V1.md#113-精致建筑与-gpt-image-样板)。本轮没有把生成图注册进游戏。

### 其他检索结果为何暂不使用

- 项目已有的 [Kenney Isometric Miniature Farm](https://kenney.nl/assets/isometric-miniature-farm) 是 CC0 的农田和构件库存。它适合作物/栏杆/室内细节；完整房屋应先离线制作成经过验收的预设，不能再用斜屋顶逐格重复铺出整栋房屋。
- [rubberduck 的 isometric buildings](https://opengameart.org/content/isometric-buildings) 是 CC BY-SA 3.0，作者引用了多种模型。与本次同作者的两个 CC0 投稿不同；没有把集合页的“CC0”标签当成该作品许可，没有下载这一包。
- [Covered well](https://opengameart.org/content/covered-well) 是 CC0 的3D模型，缺少立即可用的2D帧；同作者风格的现成井已经足够，因此不增加转换管线。
- [Stylized Wildmill](https://opengameart.org/content/stylized-wildmill-isometric-with-parts-to-build-animationand-blend) 作者标为 CC0，主要为3D源格式。第一版没有复杂农产链和磨坊需求，暂不下载；不能把“可做动画”表述成项目已经拥有连续磨坊帧。

## 建筑模式的官方参考

### Rusty's Retirement：生产需要能自动照看自己

开发者的商店介绍明确展示作物自动浇灌与采收、作物加工成燃料、辅助机器人提升自动化，以及降低生产节奏的专注模式。[开发者商店介绍](https://store.steampowered.com/app/2666510/Rustys_Retirement/)

从中推导适合本项目的做法：玩家决定优先发展什么，设施自动执行重复事务；一段时间不看屏幕，生产只是达到目标库存后停下来。不要要求点击收成、定时收菜或频繁指派角色。可以有加工、归仓等细小动作让基地值得观赏，但动画不能影响配方结算次数。

### The Wandering Village：基地保障普通需要，探索提供稀有材料

开发者官网同时介绍种植、外出收集稀有资源、不同生境旅程和可观赏的聚落；官方商店还描述生产链规划。[官网功能说明](https://thewanderingvillage.com/)、[开发者商店介绍](https://store.steampowered.com/app/1121640/The_Wandering_Village/)

从中推导的分工：基地可稳定供应基础净水、少量粮食等保障；建筑升级、好工具、特殊道具仍需外出获得矿物、皮革、药草和稀有材料。把原料到补给的链压缩成一到两步，远征继续占据主要观赏时间。不同生境影响想带回什么，也让升级后的设施有新的用途。

### First Feudal：岗位自动做事可借鉴，持续袭击不符合本项目目标

开发者说明给农民分配职业后可自动工作，基础石材和木料加工逐步通向制造、装备和基础设施；同一说明也包含袭击和严冬管理。[开发者商店介绍](https://store.steampowered.com/app/733460/First_Feudal/)

本项目只借鉴「设施职责清楚、自动完成工作」的部分。不能据此给第一版附加人口、工资、每日补给、袭击倒计时和无人值守惩罚；这些会迫使用户持续关注，与桌面陪伴目标冲突。

上述是基于官方公开机制的设计推导，并非取得其他游戏数值模型，也不是复制其素材、文案或代码。

## 建议采用的设施模式

### 设施是能力入口，等级是有限的改进

第一版先做少数唯一设施，避免建十栋相同铁匠铺才有产量的经营压力。升级优先提供可解释的帮助：可做的新配方、单批大小、目标库存上限、补给效率和适度加工速度；避免每级都把掉落、负重、速度、攻击一起倍增。

| 设施职责 | 获得的帮助 | 经济边界 |
|---|---|---|
| 核心营舍 | 归来休整、升级入口、远征预设 | 不直接不断增加战斗倍率 |
| 仓储 | 原料分类、材料安全归仓、生产预留 | 满仓自动减采/优先转化，不销毁收获制造焦虑 |
| 水井与基础补给 | 净水等基础保障、行前自动装填 | 基地产水无需外出搬水；外出的特殊水样仍另算 |
| 木工加工 | 原木/石材变成建材和简单工具 | 消耗真实原料；不把“一块板”同时算整块木料的重量 |
| 金属加工 | 矿石与燃料变金属和部件 | 没有铁矿就停；不凭时间制造铁矿、银矿或晶石 |
| 补给/药草加工 | 食材或药草变口粮、药剂 | 自动保持目标库存，基础探索缺补给也可安全继续 |

具体建筑个数、配方和升级费用以第一版经济设计为准，不能因找到了马厩或风车素材就扩大玩法。

### 自动生产需要四个约束

1. **有限目标**：设置所需成品库存，达到后不再生产；用户可以只选“保持少量补给”等默认预设。
2. **原料预留**：先预留升级目标和下一次远征补给，再使用余量加工。并发设施不能分别认为同一批木料可用。
3. **事务结算**：开工扣料/预留、完工入库和重启恢复必须有明确状态；刷新不能重新扣料或重复产出。缺料时显示“等下一次归来”，不报错催用户。
4. **保守时间**：生产时间使用游戏既定模拟时钟。关闭、休眠或网页隐藏后的进度是另一个需要显式设计的规则，第一版不能暗中套用墙上时间发放收益。

原料和成品的计量需遵守统一物品模型：矿物、液体和散装原料以质量表达；工具、瓶装道具、装备和纪念品以数量表达，但每件仍有质量用于负重。配方要同时声明输入量、输出量、燃料和废料/损耗，不能把质量单位与“图标个数”混用。

### 对抗性检查

- **能否不再探索也产出升级所需全部材料？** 若能，应限制基地只自给基础补给或加工已回收原料；稀有矿物和独特生境原料留在远征。
- **生产倍率与采集倍率是否相乘后失控？** 优先提高舒适度和配方选择，有限加速；不要用指数涨价硬压指数涨产。
- **自动加工会不会吞掉正在攒的建筑材料？** 必须有统一预留和清楚的库存摘要。
- **满仓/断料会不会变成需要立即处理的红色警报？** 应正常停工、降低采集目标或继续纯探索，角色不因此死亡或丢包。
- **建筑效果是否只为多一个计时条？** 每项设施都应改变可用产物或出发体验，并有可辨认的视觉职责。
- **是否必须等运输NPC走到门口才真正归仓？** 第一版保持既有原子归仓；NPC动画是表现。将来独立物流玩法需要再次设计，不顺带制造阻塞。
- **完整大楼会不会把角色和资源遮没？** 先在基地面板展示插画，再小范围接世界；进屋切面、门口前后关系和大物件排序各自验收，不能单靠增加 z 值。

## 分阶段使用素材

1. 设计确认后，仅把首批会有实际功能的完整建筑/井注册到专属 camp manifest。延续现有 `id → frame → image` 路径和按包加载；原野生成器版本不变。
2. 先做基地管理界面的建筑插画与真实配方、仓储和升级。建筑卡片展示真实库存、缺口、效果和生产状态，缺功能的图不做可点击的假入口。
3. 小范围营地可视化：设施身份与建筑占地分离；完整外观＋少量道具组成预设，并给烟气、搬运、加工安排观赏动作。新增预设不能改变已经保存的自然世界坐标。
4. 正式二次元主题时统一建筑、角色、植被、地面、照明和图标。替换帧描述即可换视觉，设施规则和库存 ID 保持稳定。
